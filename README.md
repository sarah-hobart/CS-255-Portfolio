## DriverPass Project Reflection

### Project Summary
The DriverPass project was for a client named Liam who wanted a system to help students prepare for their driving tests. The system would allow students to take online practice tests, access training materials, and schedule driving lessons. It would also allow employees and administrators to manage customer accounts and appointments.

### What I Did Well
I think I did well at understanding the client's needs and turning them into requirements for the system. I was able to identify the main features the system needed and organize them into documents and diagrams. I also learned how to use different modeling techniques to show how the system would work.

### What I Would Improve
If I could revise one part of my work, I would improve my diagrams to make them easier to read. Some diagrams had a lot of connections, which made them look crowded. I would spend more time organizing the layout and making sure each connection clearly shows how the system should work.

### Understanding the User's Needs
I interpreted the user's needs by reviewing the information provided about DriverPass and identifying the problems the client wanted to solve. I used those needs to decide which features the system should include, such as practice exams, lesson scheduling, and account management. Considering the user's needs is important because the system needs to solve the client's problem and work the way the users expect it to.

### My Approach to Software Design
When designing software, I would start by understanding the problem and gathering information about what the client needs. Next, I would identify the system requirements and use diagrams to plan how the different parts should work together. In the future, I would use interviews, use case diagrams, activity diagrams, sequence diagrams, and class diagrams to better understand the system and create a design that meets the user's needs.
